**日期**: 2026-07-24
**施做者**: opencode (deepseek-v4-flash)

## 問題描述與修改

### 1. 預設優先級 (Default Priority)
- **問題**: 任務不指定優先度時就完全沒有優先級，排序和顯示缺少一致的行為
- **解決**: 新增 `default_priority` 設定（預設 `(C)`），無優先度的任務在顯示/排序/篩選時視同有此優先級
- **實作**:
  - 新增 `getEffectivePriority(t)` 輔助函數，回傳 `t.pri || config.default_priority`
  - 設定頁新增下拉選單（A-Z 及「-」無預設）
  - 顯示、排序、篩選改用有效優先度
  - 儲存時不寫入預設值（動態套用，不影響檔案內容）

### 2. 點擊任務名稱複製 +/@ 至過濾欄
- **問題**: 點擊任務名稱時，`+` 專案和 `@` 標籤被移除，只複製純文字
- **解決**: 保留 `+` 和 `@` 標籤，一併加入過濾欄

### 3. 預設展開專案設定 (Expand Projects)
- **問題**: 專案選單和項目檢視器的樹狀節點預設全部展開，使用者無法調整
- **解決**: 新增 `expand_projects` 設定（預設 `false`），控制專案選單和項目檢視器的初始展開狀態
- **受影響範圍**:
  - 過濾器選單的階層式專案樹
  - 項目檢視器的所有節點

### 4. 項目檢視器任務群組化
- **問題**: 同一專案節點下任務過多時難以瀏覽
- **解決**: 同一節點有 3+ 任務時自動包裹在可收合群組中，附帶 toggle 按鈕
  - 「未分類」區塊也套用相同邏輯
  - 「全部展開/收合」按鈕也作用於任務群組
  - 初始狀態跟隨 `expand_projects` 設定

### 5. 設定畫面點擊遮罩關閉
- **問題**: 設定畫面只能點擊 ✕ 按鈕關閉
- **解決**: 加入 `onclick="if(event.target===this)App.toggleSettingsModal()"`，點擊背景即可關閉

## 技術細節

### 預設優先級架構
```
getEffectivePriority(t) → t.pri || config.default_priority
```
- `default_priority` 為空字串時表示「無預設」
- `pri=!` 篩選仍檢查 `t.pri`（明確無優先度），而非有效優先度
- 排序時無明確優先度的任務以預設值參與比較

### 任務群組化條件
- 同一 `.pv-children` 下直接任務數 >= 3 時觸發
- 使用 `.pv-task-group` / `.pv-task-group-header` / `.pv-task-group-body` CSS 類別
- `toggleAllProjectViewNodes()` 同步處理群組展開/收合
