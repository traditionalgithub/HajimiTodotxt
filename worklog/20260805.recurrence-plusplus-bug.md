# 工作總結 — rec:++ 重複任務日期計算嚴重 Bug 修復

**日期**: 2026-08-05
**施做者**: opencode (deepseek-v4-flash)

---

## 問題描述

使用者測試 `rec:++1d` 的重複任務時，完成任務後產生的下一個任務到期日嚴重錯亂：

| 原任務到期日 | 完成時 | 實際產生的下一個到期日 | 預期到期日 |
|-------------|--------|----------------------|-----------|
| 2025-12-05 | 2026-08-05 | 2026-08-08 | 2026-08-06 |
| 2026-07-30 | 2026-08-05 | **2026-09-02** | 2026-08-06 |

兩個案例的到期日都與隱藏日（threshold）一致地偏移，第二個案例差了近一個月，屬於嚴重 bug。

## 根因分析

Bug 位於 `index.html` 的 `handleRecurrence()` 的 `prefix === '++'` 分支：

```js
const base = new Date(t.due);
let add = val;
let testDate = new Date(base);
while (testDate <= new Date(today)) {
    if (unit === 'm') testDate.setMonth(base.getMonth() + add);
    else if (unit === 'y') testDate.setFullYear(base.getFullYear() + add);
    else testDate.setDate(base.getDate() + add);   // ← 錯誤
    add += val;
}
```

**誤解了 `Date.prototype.setDate(n)` 的語意**：

- `setDate(n)` 是「把該日期物件的**當月日期**設為 n」（n 可越界溢位到下個月），**不是**「基準日加 n 天」
- 每次迭代 `testDate` 已從 `base` 前移，但傳入的 n 卻是用 `base` 的日期 + 遞增的 `add` 計算
- 當 `testDate` 已到 8 月 1 日而 `setDate(30 + 3 = 33)` 被呼叫時，8 月 1 日 + 32 天 → **2026-09-02**，直接跳到下下個月
- `d`（天）單位尤其嚴重，因為日期的日號是「相對當月」的；而 `m`/`y` 單位恰好因為月/年是絕對索引而沒受影響

以 Node 在 Asia/Taipei、UTC、America/Los_Angeles 各時區均重現了 `2026-08-08` 與 `2026-09-02` 兩個錯誤結果。

## 修復方式

改為每次迭代直接從 `testDate` 本身加上 `val`：

```js
const base = new Date(t.due);
let testDate = new Date(base);
while (testDate <= new Date(today)) {
    if (unit === 'm') testDate.setMonth(testDate.getMonth() + val);
    else if (unit === 'y') testDate.setFullYear(testDate.getFullYear() + val);
    else testDate.setDate(testDate.getDate() + val);
}
newDue = testDate.toISOString().split('T')[0];
```

- 語意不變：從原到期日起，找出**嚴格晚於今天**的第一個 `base + n*val` 倍數日
- `m`/`y` 單位改為 `testDate.getMonth()/getFullYear()` 為基，與修正後一致且更清晰

## 驗證

以 Node 重現並驗證修復後結果（Asia/Taipei 與 UTC 均為 **2026-08-06**）：

```
Asia/Taipei      case1: 2026-08-06  case2: 2026-08-06
UTC              case1: 2026-08-06  case2: 2026-08-06
America/Los_Angeles case1: 2026-08-05 case2: 2026-08-06
```

- 兩個案例在 UTC+8 皆得到正確的「今日 + 1 天」結果
- inline script 以 `new Function()` 語法檢查通過

> 註：America/Los_Angeles（負時區）case1 顯示 08-05 是既有的「純日期字串以 UTC 解析、經本機時區運算後以 UTC 輸出」的日期字串時區現象，非本次 bug 造成，且不影響 UTC+8 使用者；本次修復未觸及。

## 技術細節

### `++` 重複語意（todo.txt 慣例）
- `rec:1d`：以原到期日 + 1 天（不與今日對齊）
- `rec:+1d`：以今日 + 1 天
- `rec:++1d`：從原到期日起，取第一個 `due + n*1d` 且 > 今天的日期
