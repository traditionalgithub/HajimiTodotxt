# 2026-11-21 日期高亮／快速改期與「儲存並完成任務」

- 施做時間：2026-11-21 02:25 CST
- 涉及版本：HajimiTodotxt v8.5

## 問題描述

1. 任務標題與任務描述中的日期沒有視覺區分，無法快速判斷是未來、今天或過期。
2. 想修改標題／描述中的日期時，只能手動選取整段文字重新輸入，不方便。
3. 在描述欄按「插入現在時間」時，凌晨時段常插入前一天的日期。
4. 編輯重複任務時，需要「儲存」再「勾選完成」兩步，往復操作繁瑣。

## 問題癥結

- 任務渲染只對 `+專案`、`@情境` 做高亮，日期仍是一般文字。
- 日期修改沒有專屬互動層，只能依賴文字編輯。
- `insertDateToDesc()` 使用 `new Date().toISOString().split('T')[0]` 取日期；`toISOString()` 是 UTC，在 UTC+8 的凌晨會得到前一天。`render()` 中的「明日」也有同樣的 UTC 取日期問題。
- 「儲存並完成」若直接串接 `saveTaskData()` 與 `completeTask()`，會各自觸發一次 `sync()`，兩個非同步寫入可能競爭，造成 todo/done 檔案內容不一致。

## 解決原理與思路

### 日期識別與三色高亮

- 新增 `DATE_TOKEN_SOURCE` 正則，支援：
  - `[YYYY-MM-DD]`、`[YYYY-MM-DD HH:MM]`、`[YYYY-MM-DD HH:MM:SS]`
  - `[]` 內多餘空格（例如 `[ 2026-11-01 07:09 ]`）
  - `-` / `/` / `.` 日期分隔與 `T` / 空白時間分隔
  - 無括號的裸日期 `YYYY-MM-DD`（可含時間）
- 以本地 `todayStr()` 做字串比較，分為 `future` / `today` / `past` 三類，分別套用 `--success`、`--accent`、`--danger` 顏色，隨主題自動變化。
- 渲染時先切出日期 token，其餘片段才套用原有專案／情境高亮，避免日期內容被 `\S+` 規則吞掉或插入 HTML 到屬性中。

### 懸停／游標停駐快速改期

- 新增全域 `#date-action-popover`，內含「改為今天」與「改為現在的時間」兩顆按鈕。
- 任務列表與專案概覽中的日期 `<span class="hl-date">` 帶有目標任務索引、欄位（`sub` / `desc`）與第幾個日期，滑鼠移入即在日期上方顯示氣泡；移動到氣泡上不會消失。
- 日期氣泡操作會直接改寫任務物件並 `sync()`，再重新渲染主列表與已開啟的專案概覽。
- 編輯視窗的標題／描述 textarea 會偵測游標是否落在日期 token 內；若是，使用鏡像 div 量測游標座標，在游標上方顯示同一氣泡，套用後只修改 textarea 內容，等使用者按儲存才寫入。
- 保留原本是否有 `[]`：帶括號者輸出 `[新值]`，裸日期維持裸日期。

### 本地時間修正

- `insertDateToDesc()` 改用 `todayStr(now)` 與 `pad2()` 組成本地 `[YYYY-MM-DD HH:MM]`。
- `render()` 的明日日期改用 `todayStr(tomorrow)`，避免 UTC 跨日。

### 儲存並完成任務

- 新增 `App.saveTaskAndComplete()` 與編輯視窗底部綠色按鈕。
- `saveTaskData()` 增加 `options.skipSync`：先更新記憶體中的任務與畫面，但不立即寫檔。
- 完成流程只呼叫一次 `completeTask()`，由它統一 `sync()`；重複任務因此只會產生一筆新任務，不會有兩次競爭寫入。
- 編輯已完成任務時，按鈕僅執行儲存，不會重複完成。
