# 2026-11-24 日期快速改期氣泡限縮為僅編輯視窗可用

- 施做時間：2026-11-24 16:53 CST
- 涉及版本：HajimiTodotxt v8.7

## 問題描述

主界面瀏覽任務時，滑鼠懸停或點任務標題中的日期，會浮出「改為今天／改為現在的時間／指定日期…」氣泡，可直接就地修改任務日期。使用者希望這個改期功能只在任務編輯視窗出現——瀏覽時日期單純用來辨識（三色顯示），不能就地改。

## 問題癥結

日期氣泡有兩種觸發模式：

1. **render 模式**：`buildDateSpan()` 在渲染後任務標題／描述時產生 `<span class="hl-date" data-date-target=...>`，由三個全域事件觸發：`initEventDelegation()` 中的 task-item 點擊、`initDatePopover()` 中的 document `mouseover` / `mouseout` 與 document `click`。套用後直接改寫 `tasks` / `doneTasks` 並 `sync()`。
2. **textarea 模式**：編輯視窗的 `#inp-sub` / `#inp-desc` 以游標是否落在日期 token 內觸發，套用後只改 textarea 內容，等使用者按儲存才寫入。

三處全域事件不分青紅皂白對所有 `.hl-date` 生效，因此主列表、描述區與專案概覽都能就地改期。

## 解決原理與思路

- 保留 textarea（游標）模式，移除所有 render 模式的觸發點：
  - task-item 點擊中對 `.hl-date` 的提前返回改為註解說明，讓日期點擊回落成原本的「標題過濾」行為（即日期高亮功能加入前的行為）。
  - 移除 `initDatePopover()` 中的 `mouseover` / `mouseout` 監聽，並把 document `click` 監聽縮減為「點擊氣泡與兩個 textarea 以外之處就關閉氣泡」。
- 移除不再使用的 render 模式程式碼：`showDatePopoverForSpan()`、`applyDatePopoverAction()` 的 render 分支、`refreshAfterDateEdit()`、`replaceNthDateToken()`。
- `buildDateSpan()` 不再輸出 `data-date-target` / `data-date-done` / `data-date-field` / `data-date-nth`；`renderSubjectHtml()` / `renderDescHtml()` 不再需要 `meta` 與 `nth` 參數，四個呼叫點一併簡化。
- CSS：`.hl-date` 移除 `cursor: pointer` 與 `.hl-date:hover` 背景，避免暗示可點擊；三色與底線仍保留。

## 驗證

`node --check` 通過。以 Chromium headless + 攔截 `/api/read` 的測試頁驗證：

- 主列表日期 `<span class="hl-date">` 仍存在且有三色 class，但不再帶 `data-date-*` 屬性。
- 主列表日期 `mouseover` 與 `click` 都不會顯示氣泡。
- 專案概覽中的日期 `mouseover` / `click` 也不會顯示氣泡。
- 編輯視窗文字游標停駐在 `[2026-12-31]` 上仍會顯示氣泡；點「改為今天」後文字變為 `[2026-11-24]`，氣泡關閉。
